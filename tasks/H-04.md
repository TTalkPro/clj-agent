# H-04 provider 迁到 clj-http（门面保留公开 API）

> 设计依据：[designs/http-module.md](../designs/http-module.md) §5（provider）§1.3（判定口径不变）。依赖：H-01 H-02 H-03
> 状态：✅（2026-11-09）

## 范围
- `provider/deps.edn` 加 `im.ttalk/clj-http`；`build.clj` provider 的 `:override-libs` 加它。
- `provider.http.client` 变门面：公开函数签名与返回形状逐字不变（含 `put` / `patch` / `delete` / `*-async` 回调版），
  内部改调 `http/request(-async)`；JSON 编解码、`{:status 0 :error …}` 约定、`:as :json` 回退原串留在门面。
  `default-client` 改为指向 `http/default-client`（保留 var，宿主可能引用）。`:as :stream` 的名不副实写进 docstring（行为不变）。
- `stream_client/post-stream-async` 改建在 `http/stream-lines` 上；超时异常 ⇒ `:timeout-error`（`:first-byte-timeout` / `:idle-timeout`），
  非 2xx ⇒ `response->error`，IO 错 ⇒ `errors/exception->error`；`post-stream-sync` / `-deferred` 不动。
- `retry.clj` 的 `header-get`、`rate_limit.clj` 的 `header-get` 改调 `http/header`；`parse-retry-after` 改调 `http.date`
  （多支持两种日期格式与 `retry-after-ms` 头；封顶仍是 `min(值, :max-delay)`）。
- `errors/exception->error` 用 `http.failure/classify` 补 `:code`；`:retryable?` 判定不变。

## 验收
- provider 现有测试**一条不改**全过（含 `client_test` / `stream_client_test` / `retry_test` / `reliability_http_test` 与各家 provider 测试里的 `with-redefs`）。
- 新增：Retry-After 的 RFC 850 / asctime / `retry-after-ms` 三条；DNS 失败与连接拒绝的 `:code` 不同。
- `examples/minimax_stream_test.clj` 能加载；有 key 时真机跑一次流式（MiniMax 或智谱），记录结果。
- `bb test` 全绿。

## 完成记录
- `provider.http.client` 改门面（公开函数签名 / 形状不变，`default-client` var 保留指向共享 client）；`stream_client`
  的 `post-stream-async` 建在 `stream-lines` 上；`retry/parse-retry-after` 走 `http.date`，`compute-backoff` 转调 core 版（§8）；
  `rate-limit/header-value` 走 `http/header`；deps 加 http。
- 网络错 `:code` 在 `stream-client/io-error` 补（core 不能依赖 http，设计 §5 已改）。
- 顺带修：IO 失败 `:error nil`（ConnectException 无 message）、`request-id` 回 List（设计 §9.4）。
- 测试：现有 152 个一条不改全过；新增 `http/migration_test.clj` 6 个（三种日期 / 小数秒 / `retry-after-ms`、request-id、
  rate-limit 取头、流式 DNS 失败 vs 连接被拒的 `:code`、IO 失败形状）⇒ 158 tests / 788 assertions。
- 真机（2026-11-09，本机 LiteGate 网关，OpenAI 兼容端点，`openai-compat-provider`）：
  - **MiniMax-M3.1-Flash**：sync 2.9s / stream 2.7s（11 块增量）/ async 2.0s / stream-async 2.9s 均 `finish stop` 正文完整；
    非流式与流式工具调用都得 `tool_calls`（参数 `{"city": …}` 正确）；流式第 5 块时取消 ⇒ 空响应不抛；
    `:first-byte-ms 50` ⇒ `{:type :timeout-error :code :first-byte-timeout :retryable? true}`（52ms）；4 路并发 5.5s。
  - **glm-5.3-flash**：同上各路径通过（200 token 预算被 reasoning 用完，`finish length`，属模型行为）；
    错模型名 ⇒ `:validation-error` 404、错 key ⇒ `:auth-error` 401，均不可重试，`:request-id` 现为字符串。
  - 另：无凭证打 MiniMax 公网 Anthropic 端点，同步与 `post-stream-sync` 均得 401 ⇒ `:auth-error`（真实 TLS + 非 2xx 路径）。
