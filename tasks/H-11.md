# H-11 Netty transport adapter

> 设计依据：[designs/provider-http-transport.md](../designs/provider-http-transport.md) §2 §7.3 §8.1 §9 §10。依赖：H-07 H-08 H-09 H-10
> 状态：✅ 完成（2026-11-18）

## 触发条件

只有在 Apache adapter 落地后，出现以下任一真实需求才启动：

- 有部署场景需要 Netty 的连接 / TLS / proxy / 协议能力，且 Apache adapter 无法满足；
- 有实测吞吐、连接复用或协议兼容数据支持换 Netty；
- 宿主已有 Netty 基础设施，要求 provider 共用该运行时。

不得只因“Netty 更异步 / 更高性能”启动本任务。

本轮触发：宿主要求共用已有 Netty 基础设施（用户明确要求补齐本模块）。

## 范围

- 新增可选模块 `modules/clj-http-netty`，坐标 `im.ttalk/clj-http-netty`，ns `im.ttalk.http.netty`。
- Netty 依赖只进该模块；不进 `clj-http`、provider、core。
- 实现 `http-netty/transport`：
  - `request`；
  - `request-async`；
  - `stream-lines`；
  - `close`。
- event loop group、channel pool、连接生命周期由 adapter 管理；宿主显式关闭。
- Netty pipeline 负责把 response / chunk 归一成契约形状；不把 `ByteBuf`、channel、pipeline 泄漏给 provider。
- SSE 必须逐 chunk 分帧后回调，不得整包聚合。
- 不在 event-loop 线程执行 provider 的阻塞逻辑；adapter 文档写明回调线程。
- 超时覆盖 connect、request、first-byte、idle；取消必须关闭或归还 channel。
- cancel 后必须释放 `ByteBuf`、response、channel 引用，避免内存泄漏。

## 验收

- Netty transport 通过同一组 transport contract test。
- 回环服务覆盖：
  - 同步 / async / stream；
  - chunked response；
  - SSE 逐行到达；
  - 非 2xx；
  - first-byte timeout；
  - idle timeout；
  - cancel；
  - connect 失败、DNS 失败、TLS 失败；
  - 重复 close 安全。
- provider 可用 `:http-transport (http-netty/transport ...)` 跑通四条路径；缺省 provider 依赖不变。
- 压测或长跑记录中不得出现 ByteBuf 泄漏、channel 泄漏、event-loop 阻塞。
- `bb test http` 与 `bb test http-netty` 全绿；`bb test provider` 全绿；`bb test` 全绿。

## 施工记录

- v1 每条请求单独建连并发送 `Connection: close`；不实现 channel pool 与 redirect，
  `:pool` / `:redirect` 抛 `:invalid-request`。
- 支持注入 `EventLoopGroup`（`transport/close` 不关闭注入值）或自建 Nio event loop。
- 回环测试覆盖同步 / async / stream、多值头、bytes / discard、非 2xx、取消、
  first-byte timeout、DNS / connect / TLS 错误、`:pool` / `:redirect` 校验与重复 close。
