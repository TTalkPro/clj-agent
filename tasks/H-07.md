# H-07 HTTP transport 契约与错误归一化

> 设计依据：[designs/provider-http-transport.md](../designs/provider-http-transport.md) §2 §3 §4 §8.1。依赖：无
> 状态：✅（2026-11-18）

## 范围

- 新增 `im.ttalk.http.transport`，只放 transport 契约与纯 helper，不引第三方 HTTP client 依赖。
- transport 是普通 map，必填 `:request`、`:request-async`、`:stream-lines`、`:capabilities`；可选 `:name`、`:close`。
- 提供 facade：
  - `transport/request`；
  - `transport/request-async`；
  - `transport/stream-lines`；
  - `transport/transport?`；
  - `transport/assert-transport!`；
  - `transport/close`。
- 提供 request / response / headers 的归一化 helper：
  - 请求 header 归一成小写 key + string vector；
  - 有 body 且无 `content-type` 时补 `application/json`；
  - response header 归一成小写 key + string vector；
  - request body v1 只允许 `nil` / string / bytes。
- 提供 transport exception helper 与谓词：
  - `:name-resolution-error`；
  - `:connection-error`；
  - `:secure-connection-error`；
  - `:timeout-error`；
  - `:cancelled-error`；
  - `:unknown-io`；
  - `:invalid-request`；
  - ex-data 约定使用 `::transport/error`、`::transport/cause`、`::transport/data`。
- 不改现有 `im.ttalk.http/request`、`request-async`、`stream-lines` 公开行为。
- 不做 JSON、重试、SSE 事件解析、canonical error、限流头解释。

## 验收

- `transport?` / `assert-transport!` 覆盖缺函数、缺 capabilities、capabilities 不是 set、close 不是函数。
- facade 缺函数时尽早抛 `:invalid-request`，不发网络请求。
- header 归一化覆盖：字符串 key、关键字 key、大小写混合、单值、vector、`java.util.List`。
- body 校验覆盖：nil、string、bytes 通过；integer、map、input-stream 拒绝。
- response helper 覆盖：大写 / 混合 header、多值 header、`:as :string` / `:bytes` / `:discard`。
- transport exception 覆盖：kind 与 ex-data 保留原始 cause；`:invalid-request` 不被当 IO 错。
- `bb test http` 全绿。
