# H-09 provider 接入 `:http-transport`

> 设计依据：[designs/provider-http-transport.md](../designs/provider-http-transport.md) §5 §6 §8.2 §8.3。依赖：H-07 H-08
> 状态：✅（2026-11-18）

## 范围

- provider 新增进程级缺省 transport：JDK transport，构造参数与现 `default-client` 等价。
- `provider.http.client` 新增并贯通 `:http-transport`：
  - `request`；
  - `request-deferred`；
  - 便捷方法 `get` / `post` / `post-deferred` / `post-json` / `get-json`；
  - 已发布 API 的函数签名与返回形状不变。
- 修复现状：非流式请求不再固定使用 `@default-client`，而是解析 `:http-transport`；没有给时才用缺省 transport。
- `provider.http.stream-client` 的 `post-stream-async` / `post-stream-sync` / `post-stream-deferred` 贯通 `:http-transport`。
- chat provider 配置传递 `:http-transport`，覆盖四条路径：
  - 非流式同步；
  - 非流式 deferred；
  - 流式同步；
  - 流式 deferred。
- 覆盖实现：
  - OpenAI compatible；
  - Anthropic；
  - OpenAI Responses；
  - DashScope；
  - embeddings（按其现有调用面接入，通常只有非流式路径）。
- provider 识别 H-07 的 transport exception，并继续归一成现有 canonical error：
  - IO 型失败仍产生 `{:status 0 :error ... :success? false}`；
  - `Retry-After`、限流头、业务码、可重试性、模型核对语义不变；
  - `:invalid-request` 不转成网络错误。
- 迁移期兼容：
  - 流式旧 `:client` 保留，只接受 JDK `HttpClient`，包成 JDK transport；
  - 非流式旧 `:client` 接受，也包成 JDK transport；
  - `:http-transport` 优先于 `:client`；
  - 不把 `:client` 扩展成任意 client 类型。
- 不引入动态全局变量切换 transport；测试使用显式 fake transport。

## 验收

- 新增 fake transport，验证 provider 四条路径都使用注入值。
- 验证配置优先级：`:http-transport` > `:client` > 缺省。
- 验证所有列出的 provider 实现能按其调用面把 `:http-transport` 传到底层：
  - OpenAI compatible；
  - Anthropic；
  - OpenAI Responses；
  - DashScope；
  - embeddings。
- transport exception 映射覆盖 DNS、connect、TLS、超时、取消、未知 IO、invalid request。
- `Retry-After` 在小写 key + vector 值形状下仍能解析。
- 流式回归覆盖非 2xx、取消、first-byte timeout、idle timeout、`on-token` 未产出前重试。
- 现有 provider 测试除注入点外不应出现行为性修改；公开 API 回归全绿。
- `bb test provider` 全绿；最后跑一次 `bb test`。
